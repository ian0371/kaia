# Permissionless Validator Join — Live Demo

Demonstrates Kaia's permissionless consensus: a new node generates a key, stakes,
and joins the active validator set at the next epoch — no governance vote, no manual approval.

The "whoa" moment: validator count grows **4 → 5** on a live dashboard, then **5 → 4** — all driven from a browser.

## Prerequisites

- Kaia binary built from this branch (`kaia`, `kgen`, `homi` in PATH)
- [kaiaspray](https://github.com/kaiachain/kaiaspray) cloned at `~/kaia/kaiaspray/`
- [Foundry](https://getfoundry.sh/) — `cast` in PATH
- Python 3 and OpenSSL

## Step 1 — Build

```bash
# From repo root
make all
```

## Step 2 — Start the 4-node network

```bash
bash demo/permissionless/setup.sh
```

Starts a 4-validator devnet with a **100-block epoch** (~100 seconds). Genesis uses the
`test,junk` mnemonic so funded account keys are deterministic and reproducible.

## Step 3 — Open the dashboard

```bash
python3 -m http.server 9000 --directory demo/permissionless
```

Open **http://localhost:9000/dashboard.html** in a browser. You should see 4 validators.

> Note: open the dashboard via `http://` (not `file://`) to avoid browser CORS restrictions
> on `fetch()` calls to `localhost:8551`.

## Step 4 — Join as a new validator

### Option A — terminal script

In a new terminal:

```bash
bash demo/permissionless/join.sh
```

The script generates a fresh nodekey, deploys staking, stakes 5 M KAIA, registers in ABv2,
and signals `readyCandidate`. At the next epoch the dashboard shows **4 → 5**.

### Option B — dashboard demo controls

The dashboard includes an interactive **Demo Controls** panel (requires internet for ethers.js CDN).
After `join.sh` runs once, use the dashboard buttons to cycle CN5 in and out of the validator set
without touching a terminal:

| CN5 State     | Button available    | What happens                                  |
|---------------|---------------------|-----------------------------------------------|
| `Registered`  | ⬆ Signal Ready      | `readyCandidate` → CandReady                  |
| `CandReady`   | — (epoch pending)   | System promotes to ValActive at epoch boundary|
| `ValActive`   | ⬇ Exit Validator    | `exit` → ValExiting                           |
| `ValExiting`  | — (epoch pending)   | System demotes to ValInactive at epoch boundary|
| `ValInactive` | ⬆ Reactivate        | `offboard` + `readyCandidate` → CandReady     |

> **Note:** The demo controls embed the CN5 keys from `cn5/keys/nodekey` (generated by `join.sh`).
> If you reset the network (`rm -rf cn5/`), run `join.sh` once to regenerate the keys, then
> update `CN5_NODEKEY`, `CN5_NODEID`, `BLS_PUB`, and `BLS_POP` constants in `dashboard.html`.

At each epoch boundary the dashboard updates: count jumps **4 → 5** (onboard) or **5 → 4** (offboard),
new/departing address highlighted.

## How it works

`epochBlockInterval` is baked immutably into the `AddressBookV2` bytecode at genesis
via `AllocPermissionlessConfig.EpochBlockInterval`. `VRankEpoch` controls the Go-side
epoch boundary check. Both are set to **100** for the demo via `homi --vrank-epoch 100`.

At each epoch block, the Go consensus engine promotes `CandReady` nodes to `ValActive` —
permissionlessly.

```
kgen → stake → createNode → readyCandidate → [100 blocks] → ValActive
```

## State machine

```
Unknown ──join.sh──► CandReady ──epoch──► ValActive
                         ▲                    │
                   readyCandidate            exit
                         │                    │
                    Registered ◄─offboard─ ValInactive ◄─epoch─ ValExiting
```
